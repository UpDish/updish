## 로그인 이후 역할별 시나리오

실제 지갑과 연결되지 않은 **선택 가능한 계정 시나리오 7개**와 배경 참여자 1개입니다. 한 계정이 여러 역할을 가질 수 있습니다. 가게 조회와 투자내역은 공통이고 역할별 추가 영역을 데이터로 구분했습니다.

| persona ID | 상황 | 추가 데이터 |
| --- | --- | --- |

| investor-active | 여러 가게에 투자한 고객 | 4개 보유, 정정/미지급/부분 지급/만기, 쿠폰 |
| merchant-seongsu | 성수 가게 담당자 + 투자자 + 고객 | 본인 가게 1곳 관리, 다른 가게 보유/혜택 |

혜택 정의 8개, 발급/사용 내역 6건, 계정별 조건 판정 40건을 포함합니다. 수령 가능·수량 부족·발급 완료·사용 완료·만료·예정·소진 상태가 모두 있습니다. 코드 `DEMO-NOT-VALID-*`는 실제 사용 가능한 쿠폰이 아닙니다.

## 저장·조회

- `spec.json`: 가게/상품/월 매출 생성 기준. `pnpm generate:ux-demo`로 결정적으로 생성합니다.
- `dataset.json`: 모든 관계가 연결된 결과. `pnpm check:ux-demo`로 원본과 Core 자원의 바이트 일치를 검사합니다.
- Core 시작 시 Flyway V6의 **별도 `ux_demo_dataset` 테이블**에 이 버전을 한 번 등록합니다. 같은 ID의 다른 내용은 덮어쓰지 않고 실패합니다. 수정할 때 새 버전을 준비합니다.
- 기존 업무 원장/계정/권한/active run/온체인 작업과 분리합니다. 모든 체인 보유는 0, 체인 상태는 NOT_SUBMITTED입니다. 일반 업무의 승인/자격 검사를 우회하지 않습니다.
- 실제 OPERATOR로 로그인한 개발자만 아래 읽기 API로 점검할 수 있습니다. persona 선택은 시연 데이터 조회이며 실제 계정/권한 전환이 아닙니다.

```
GET /api/v1/workbench/demo-data
GET /api/v1/workbench/demo-data/personas/investor-active
```

Web BFF에서는 `/api/workbench/demo-data...`입니다. OpenAPI의 `UxDemoDataset`, `UxPersonaView`와 생성 TypeScript 타입을 다음 화면 개발에 사용할 수 있습니다. 개인 예시는 `portfolio`, 담당 가게는 `storeManagement`, 혜택은 `customerBenefits`, 검토는 `reviewQueue`, 운영은 `operations`로 반환합니다.
