# 성수 모퉁이 시연 CSV

가상 음식점 성수 모퉁이의 참고 매출 6개월과 업무 예외 시나리오입니다. 실제 가게·거래·승인·지급을 나타내지 않습니다.

| 파일 | 대상 월 | 정산대상 매출 | 기대 결과 |
| --- | --- | ---: | --- |
| history-2026-05.csv | 2026-05 | 22,000,000원 | POS/PG/은행 일치 · 계약 전 참고 자료 |
| history-2026-06.csv | 2026-06 | 24,000,000원 | POS/PG/은행 일치 · 계약 전 참고 자료 |
| history-2026-07.csv | 2026-07 | 27,000,000원 | POS/PG/은행 일치 · 계약 전 참고 자료 |
| history-2026-08.csv | 2026-08 | 25,000,000원 | POS/PG/은행 일치 · 계약 전 참고 자료 |
| history-2026-09.csv | 2026-09 | 28,000,000원 | POS/PG/은행 일치 · 계약 전 참고 자료 |
| normal.csv | 2026-10 | 30,000,000원 | 중복 2행 제외·부분 환불 반영, 검토 가능 |

| correction.csv | 2026-10 | 29,000,000원 | 정상 10월 승인 후 추가 환불 정정 → 배분 의무 870,000원 |

차트의 6개월은 5~9월 자료 + 10월 normal.csv입니다. 배분금은 현재 배분율을 적용한 **예시**이며 DB 정산/개인 보유/지급 내역과 별개입니다. 계약 시작 전 월은 매출 대조는 가능해도 정산은 차단됩니다.

## 앱에서 사용

- 청약 → 매출 차트: 승인 자료가 없으면 **샘플 CSV**를 기본 표시합니다. **승인 기록**으로 전환하면 실제 업무 API의 최신 승인 버전만 나옵니다. API 오류는 승인 자료 없음이나 샘플 성공으로 숨기지 않습니다.
- 차트 아래에서 월별 CSV와 흐름 점검용 4종을 내려받습니다.
- 운영자/가게 담당자 로그인 → 매출관리 → 샘플 선택 → 내용/월 확인 → CSV 제출.
- 제출자와 다른 검토 지갑으로 마감/산정하고, 산정자와 다른 승인 지갑으로 승인합니다. 운영자 화면 토글은 이 지갑 분리를 대체하지 않습니다.
- 누락 케이스는 보완 필요, 현금 부족은 의무/지급 가능액 차이, 정정은 이전 지급액 보존을 확인합니다.

## 유지·재현

`catalog.json`이 파일 목록·기대 금액·issue code·SHA-256의 원본입니다. `pnpm generate:demo`가 `apps/web/public/samples/`에 같은 바이트를 복사하며 `pnpm check:demo`로 일치를 검사합니다. CSV는 모든 OS에서 LF를 유지합니다. 원본을 바꿀 때 catalog의 기대 결과/해시도 검토해야 합니다.

Core의 `DemoCatalogTests`와 `CsvReconciliationTests`는 실제 서버 대조 함수/산식으로 파일과 기대 결과를 검사합니다. 브라우저 검사는 9개 공개 다운로드 해시 및 별도 DB의 제출/검토/정정 승인을 확인합니다. 공유 클라우드 DB를 자동 승인하거나 초기화하지 않습니다.
