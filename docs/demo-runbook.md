# Demo 시연 동선

2026-10-26 · 현재 팝업/Agent 개편은 로컬 검토본입니다. 기존 공개 배포와 구분합니다.

발표 초안의 5장 시연 흐름과 5.2 수치 예시를 참고했습니다. 이 문서는 발표의 아이디어·시장·법률 설명을 다시 작성하는 자료가 아니라 **실제 클릭 순서와 확인할 결과**입니다. 초안의 기술 제안이나 미확인 표시는 기존 승인된 구현 명세를 변경하는 지시로 취급하지 않았습니다.

## 진행 순서

1. **지갑 로그인** → 첫 탭 가게 목록. TESTNET FAUCET Dojang을 실제 신원 인증과 구분합니다.
2. **성수 모퉁이 선택** → 매출 차트·계약·위험 확인. 상세의 `청약하기`에서만 수량/동의 팝업을 엽니다. 성수 100단위는 100만원이며, 다른 가게는 그 가게 단가를 따릅니다.
3. **모의 청약 접수** → 완료 팝업 → 투자 내역. 배정 전 접수와 배정된 보유를 구분합니다. 운영자는 `시연 준비`에서 가상 배경 3,500단위를 준비하고, `모집·배정`에서 사용자 100단위를 배정합니다. 실제 지갑의 자격 검사는 유지됩니다.
4. **고객 혜택** → 배정된 보유 조건에 따른 모의 쿠폰을 확인합니다. 주문·충전·실제 결제는 구현 범위 밖입니다.
5. **가게 관리** → `매출 CSV 제출` 팝업 → 정상 샘플 선택 → 제출. 목록의 `대조 상세` 팝업에서 중복·할인·환불·입금 차이를 확인합니다. 은행 자료 누락 예시는 보완 필요이며 마감할 수 없습니다.
6. **다른 검토 지갑** → 자료 검토 → 대조 상세 → 사유 입력 → 마감 → 정산 산정. 산정자와 다른 승인 지갑으로 운영 관리의 `정산·지급` → 선택 정산의 `정산 관리` 팝업에서 승인합니다.
7. **투자 지갑 복귀** → 정산 내역 → `정산 근거` 팝업. 정상 시나리오의 매출 3,000만원 × 3% = 90만원, 100 / 3,600단위의 세전 의무액 25,000원을 확인합니다. 실제 현금 지급과 구분합니다. 지급 실패·부분 지급·정정은 각각 다른 기록으로 남습니다.
8. **Agent에게 질문** → 해당 명세를 선택한 **오른쪽 사이드바**가 열립니다. 본문 탐색 중에도 유지되며 닫았다 열어도 현재 대화를 유지합니다. 지갑/명세가 바뀌면 대화를 분리합니다. `정산 근거 열기`는 별도 팝업입니다.

상단 `시연 순서`는 화면 이동 안내만 수행합니다. 배정·승인·지급·지갑 거래를 자동 실행하지 않습니다. 별도 승인 지갑을 사용해야 합니다. 이미 모집이 종료된 경우 운영자의 `시연 준비`에서 새 시연을 시작할 수 있으며 이전 이력은 보존됩니다.

## 화면 분리 원칙

| 기본 화면 | 필요할 때 여는 작업 |
| --- | --- |
| 가게 상세·차트 | 청약 입력/동의, 접수 완료 |
| 투자 내역 표 | 취소 확인, 개인 정산 상세 |
| 가게 증빙 목록 | CSV 제출, 원문 확인, 첨부 증빙, 대조 상세 |
| 운영 작업별 탭 | 시연 준비, 역할 설정, 배정/환불/만기 확인, 선택 정산 관리 |
| GIWA 작업 상태 | 계약 배포·복구·등록 설정 |
| 본문과 나란한 Agent | 선택 명세의 근거 상세 |

팝업은 키보드 포커스를 유지하고 Escape/닫기 후 원래 버튼으로 돌아갑니다. 데스크톱 Agent는 본문을 막지 않는 도구 창이며, 850px 이하에서는 포커스를 가두는 전체 화면 채팅으로 전환합니다. 팝업 안의 근거를 닫아도 바깥 Agent는 유지됩니다.

## Agent 실제 범위

기존 Spring → FastAPI `/internal/explain` 연결을 사용하며 새 모델/키를 만들지 않았습니다. 새 GET `/api/workbench/agent/status`는 인증된 사용자가 연결 상태만 확인합니다. 모델 호출이나 비밀키를 반환하지 않습니다. 서버가 도달 가능하더라도 키가 미설정이면 `모델 미연결`로 표시하고 전송을 비활성화합니다. 원장의 근거 조회는 별도로 작동합니다. 모델 실패를 성공 답변이나 시스템 메시지로 꾸미지 않습니다.

대화는 현재 화면 메모리에만 보관하고 사용자/선택 명세별로 분리합니다. 후속 질문에는 최근 두 메시지의 짧은 참고 문맥을 기존 500자 질문 한도 안에 전달합니다. 사실 근거는 계속 서버가 허용한 개인 정산입니다. 청약·지급·지갑 서명을 Agent가 대신하지 않습니다.

## 검증

Java/PostgreSQL 전체 55개, 로컬 브라우저 25개, 기존 업무 E2E 12개, Web/체인 타입과 production build 통과. 팝업 최종 중앙 정렬도 재확인했습니다. [현재 근거](evidence/presentation-flow/). 브라우저는 별도 DB·Anvil·테스트 지갑을 사용합니다. 실제 사용자 GIWA 거래·실제 모델 답변으로 보고하지 않습니다. 공개 배포 식별자는 이전 [UX 릴리스](evidence/ux-journey/release.json) 상태를 유지합니다.
