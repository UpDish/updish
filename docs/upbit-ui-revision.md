# 업비트 화면 기준 디자인 수정 — 2026-10-31

기존 v0.3는 업무 흐름을 나눈 상태였지만 업비트의 화면 비율·정보 밀도를 충분히 반영하지 못했다. 기능 검증 통과를 시각적 완성으로 해석하지 않는다.

## 실제 기준과 변경

웨일에서 [업비트 거래소](https://www.upbit.com/exchange?code=CRIX.UPBIT.KRW-BTC)를 새로 열어 화면과 표시 스타일을 확인했다. 실제 헤더는 높이 60px, 배경 `#003597`, 본문은 Roboto / Noto Sans KR이다. 기존 조사와 함께 다음을 적용했다.

| 기준 | 변경 |
| --- | --- |
| 파란 헤더·회색 바탕·평평한 흰 패널 | 전역 색상·글꼴·탭·버튼·경계선을 통일했다. 글꼴은 자체 제공한다. |
| 촘촘한 종목 목록·숫자 우측 정렬 | 첫 탭의 가게 행을 줄이고, 청약가·모집금액·배분율을 비교한다. 실제 검색·정렬·상태 필터를 제공한다. |
| 선택한 종목과 목록의 인접 배치 | 상세에 매출 차트, 오른쪽 가게 목록과 청약 패널을 배치했다. 다른 가게 선택 시 검색은 유지한다. |
| 차트와 정보의 분리 | 매출·대조를 먼저 보여주고 확장 계획·계약 조건·위험은 별도 탭, 정확한 월별 금액은 펼침 항목으로 제공한다. |
| 모바일의 지속적인 투자 동작 | 작은 화면에서는 목록을 3개 핵심 열로 줄이고 청약 버튼을 하단에 고정한다. 금액·조건 확인은 팝업으로 진행한다. |

로고·메뉴는 UpDish의 독립 DEMO임을 유지한다. 모집금액을 현재가로, 매출 배분율을 확정 수익률로 바꾸지 않는다. 본점 참고 CSV와 2호점 승인 매출도 구분한다. 가격 캔들·호가·체결 자료를 만들어 넣지 않았다.

## 화면 순서와 확인 범위

1. **로그인 → 가게 탐색 — 통과.** 로컬 별도 지갑 SIWE, 8개 가게, 검색·정렬·필터·빈 결과 복구를 확인했다. [목록](evidence/upbit-ui-20261031/directory-desktop.png), [모바일 목록](evidence/upbit-ui-20261031/directory-mobile.png).
2. **가게 상세 → 청약 조건 — 통과.** 차트 기본 진입, 목록에서 가게 변경, 자료 구분, 금액 입력, 위험 동의 전 제출 차단, Escape 후 초점 복귀를 확인했다. [상세](evidence/upbit-ui-20261031/detail-desktop.png), [모바일 상세](evidence/upbit-ui-20261031/detail-mobile.png), [청약](evidence/upbit-ui-20261031/order-mobile.png).
3. **내 투자·가게/정산 콘솔·Agent — 통과.** 투자 탭과 업무 콘솔을 구분하고 데스크톱 비모달 채팅·모바일 모달 채팅을 유지한다. [Agent](evidence/upbit-ui-20261031/agent-desktop.png).

Next production build와 실제 Core/PostgreSQL에 연결한 브라우저 검사 39개가 통과했다. 화면 크기는 1440×900, 768×1024, 390×844, 360×844이며 가로 넘침·브라우저 실행 오류가 없었다. [검사 결과](evidence/upbit-ui-20261031/browser-checks.json), [재현 스크립트](../scripts/browser-upbit-ui.js).

이번 검사는 화면·탐색·팝업 중심이다. 청약을 실제 제출하거나 사용자의 GIWA 거래를 서명하지 않았고, 분배/정정의 전체 업무 검사를 다시 실행했다는 뜻도 아니다. 키보드 초점과 화면 맞춤을 확인했으나 전체 접근성 인증은 아니다. 업비트와 내용이 다른 서비스의 구조·스타일 적용이며 픽셀 단위 복제 완료를 주장하지 않는다.

실제 사용자 지갑이 표시된 웨일 캡처와 원본 비교 화면은 비공개 작업 폴더에 보관한다. 위 공개 캡처는 로컬 전용 테스트 지갑과 가상 자료다. 최신 공개 배포의 커밋·확인은 [팀 확인 이슈](https://github.com/UpDish/updish/issues/1)에 기록한다.
