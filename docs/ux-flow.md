# 로그인과 역할별 서비스 흐름

**현재 기준(2026-10-31):** [발표 v0.3](presentation-v03.md). 첫 두 탭은 가게 탐색·내 투자이며, 가게·자료 검토·정산·분배는 별도 콘솔입니다. 청약은 금액→조건 확인→접수, 분배 내역은 테스트 자산 수령 우선입니다. 아래 이전 구현 기록의 고객 화면과 구 수치는 현재 시연 기준에서 제외합니다.

2026-10-26 · SIMULATION · 모든 가게는 가상입니다.

로그인 → **가게 목록** → 가게 상세·차트·계약 → 청약 팝업 → **투자 내역**으로 이어집니다. 첫 두 메뉴는 모든 역할에서 동일합니다. 세 번째 **운영 투명성**은 POS 고객 결제·PG 정산·은행 입금을 대조합니다. 고객을 별도 사용자 역할로 두지 않고, 결제 데이터를 가게 운영의 근거로 사용합니다.

| 실제 역할 | 공통 메뉴 이후 |
| --- | --- |
| 투자자 | 추가 관리 메뉴 없음 |
| 가게 담당자 | 가게 관리 |
| 검토자 | 자료 검토 |
| 운영자 | 가게 관리, 자료 검토, 운영 관리 |

내 지갑은 상단에서 엽니다. 운영자의 관점 전환과 여섯 가상 계정 예시는 설명용이며 실제 권한을 바꾸지 않습니다. 예시 상태에서는 청약·승인·모델 호출을 실행하지 않습니다.

가게 상세의 ‘결제·정산 대조로 운영 투명성 확인’으로 해당 가게에 바로 진입합니다. 기본값은 해당 가게의 승인 원장이 있으면 승인 원장, 없으면 명시된 가상 CSV입니다. 정상/은행 누락/PG 불일치/환불 정정 네 예시는 서버의 실제 CSV 파서를 사용합니다. 자료 누락은 0원이 아닌 null/자료 없음입니다. 대조 일치는 승인이나 지급이 아닙니다. 검토 중인 금액과 고객 거래 원본은 공개하지 않습니다.

Agent는 IDE처럼 오른쪽에 여는 채팅입니다. 작은 주제 선택, 대화, 하단 입력창만 둡니다. 가게 공개 대조와 이용 안내는 투자 이력이 없어도 질문할 수 있습니다. 투자 내역의 ‘Agent에게 질문’은 본인의 승인 정산으로 연결됩니다. 근거는 접어서 확인하며 내부 ID는 본문에서 읽기 쉬운 이름으로 표시합니다. 지갑·명세·명시적 주제가 바뀌면 대화를 분리하고, 일반 탭 이동과 닫기/다시 열기에서는 유지합니다. 대화 자체는 화면 메모리에만 있습니다.

## API와 데이터

일반 로그인 지갑은 `/market`, `/investments`, `/transparency/{storeId}`, `/agent/status`, POST `/agent/chat`을 사용합니다. 개인 정산 설명은 기존 `/settlements/{id}/explain`이며 소유 확인을 유지합니다. 모든 POST는 SIWE 세션·CSRF·정확한 Origin이 필요합니다. 공개 근거 Agent에는 승인 매출 집계, 라벨된 가상 CSV와 이용 안내만 전달합니다. 모델은 읽기 도구 1회, 근거 ID/버전 검사, 캐시와 사용량 제한을 사용합니다.

고객/쿠폰 API는 410을 반환하고 더 이상 발급하지 않습니다. 기존 `benefit_claim`과 immutable v1 fixture는 역사 자료로 보존합니다. OPERATOR persona 조회에서는 `customer-only`를 거부하고 CUSTOMER 역할·혜택을 노출하지 않습니다. 전체 역사 dataset API는 계속 OPERATOR 전용입니다. V8은 agent_run의 settlement_id만 nullable로 바꾸며 이전 기록을 삭제하지 않습니다.

성수 현재 상품, 연남·망원 catalog 상품의 모의 청약을 유지합니다. 다섯 역사 상태 상품은 읽기 전용입니다. 현재 지갑 투자 내역과 가상 persona 보유를 혼합하지 않습니다. 네 눈 검토, 사유, 계약 기간, 소유권, Dojang과 체인 safe 검사를 유지합니다.

검증: Java 58, Python 4(fake SDK), 로컬 업무 E2E 12, persona HTTP 11, 브라우저 18. 실제 모델 응답은 별도 [transparency-agent 근거](evidence/transparency-agent/)에 보관합니다. UI/업무 지갑과 계약은 로컬 Anvil이며 GIWA 거래로 보고하지 않습니다. 예전 browser-journey 스크립트/근거는 고객 기능을 포함한 역사 기록입니다. 현재 UI 검사는 `scripts/browser-transparency.js`, 업무 검사는 `pnpm smoke:business`를 사용합니다.
