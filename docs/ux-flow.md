# 로그인과 역할별 서비스 흐름

2026-10-26 · SIMULATION · 모든 가게는 가상입니다.

## 기본 동선

비로그인 상태에서는 지갑 선택과 SIWE 로그인부터 안내합니다. 로그인하면 **가게 목록**으로 이동합니다. 메뉴 순서는 가게 목록 → 투자 내역 → 역할별 메뉴이며, 내 지갑·Dojang은 상단 별도 진입입니다. 메뉴와 가게 선택은 URL에 반영되어 새로고침과 브라우저 뒤로 가기를 지원합니다.

가게 목록에서 검색/모집 상태로 찾고 가게명을 누르면 매출 차트·계약·위험 안내와 인접한 청약 입력을 봅니다. 수량/필수 동의/Dojang을 검사한 모의 청약은 두 번째 탭의 청약 내역에 남습니다. 배정 전 청약은 취소할 수 있습니다. 청약 접수와 배정된 보유를 구분하며, 투자 내역의 보유·청약·정산 화면에는 **현재 지갑의 모든 시연 이력**이 표시됩니다. 이전 run과 정정 버전을 지우지 않습니다.

| 실제 역할 | 공통 메뉴 이후 |
| --- | --- |
| 투자자 | 고객 혜택 |
| 가게 담당자 | 가게 관리, 고객 혜택 |
| 검토자 | 자료 검토 |
| 운영자 | 가게 관리, 고객 혜택, 자료 검토, 운영 관리 |

가게 관리는 기존 현재 가게의 CSV/비공개 첨부/대조 이력, 자료 검토는 담당 증빙의 마감, 운영 관리는 역할 지정/배정/승인/지급/체인 작업입니다. 실제 서버 권한·소유권·서로 다른 승인 지갑 검사를 유지합니다. 운영자의 화면 모드 선택은 메뉴를 줄이는 설명용 기능이며 서버 권한을 바꾸지 않습니다.

## 실제 모의 원장과 읽기 전용 예시

- 성수는 기존 현재 상품을 그대로 사용합니다. 연남·망원은 V7 이후 별도 catalog run에 추가한 모의 청약 상품입니다. 각각 자체 단가/모집 수량/시작일을 사용합니다. 초기화가 기존 active run, 보유, 정산, 체인 작업을 바꾸지 않습니다.
- 다른 다섯 가게의 배정/환불/만기는 **과거 상태 시연 예시**입니다. 임의의 실제 승인이나 보유를 원장에 만들지 않으며 신규 청약을 받지 않습니다.
- 성수의 기존 승인 매출 차트와 개인 명세를 유지합니다. 새 가게 차트는 표시된 가상 CSV 참고 수치입니다. 표본을 실제 승인 매출이나 가격/수익률로 표시하지 않습니다.
- 운영자만 ‘시연 계정 예시 보기’에서 일곱 가상 계정을 선택할 수 있습니다. 가상 보유/미지급/정정/가게 범위/혜택을 읽기 전용으로 봅니다. 실제 지갑 자료와 별도 배너로 구분하며 예시 화면에서 청약·승인·쿠폰 발급을 실행하지 않습니다.
- 고객 혜택은 실제 지갑의 **배정된 보유 수량**, 유효 기간, 전체 발급 한도를 검사합니다. 접수 중 청약은 조건에 포함하지 않습니다. 모의 수령은 지갑별로 저장하고 중복 요청은 같은 결과를 반환합니다. `DEMO-NOT-VALID-*` 코드는 실제 매장에서 사용할 수 없습니다. 사용 처리/결제 서비스는 제공하지 않습니다.

## API와 검증

인증된 일반 지갑: GET `/api/workbench/market`, `/investments`, `/benefits`; POST `/benefits/{benefitId}/claim`. 기존 `/offerings/{id}/subscribe`, `/subscriptions/{id}/cancel`을 사용합니다. 모든 쓰기에 세션·CSRF·허용된 Origin이 필요합니다. 기존 `/demo-data/personas/*`는 실제 OPERATOR 전용이며 일반 사용자에게 열지 않습니다.

V7은 `market_offering`, `benefit_claim`을 추가합니다. startup 순서는 업무 원장 → immutable fixture → 추가 catalog 상품입니다. GET 조회는 초기화/발급을 수행하지 않습니다. 쿠폰의 한도 확인과 저장은 하나의 잠금/트랜잭션으로 처리합니다.

재현: Java 전체 테스트, `pnpm check:web`, `pnpm check:chain`, `pnpm build:web`. 별도 로컬 Anvil/DB에서 `pnpm smoke:business`로 준비한 뒤 Playwright CLI의 `scripts/browser-journey.js`, `scripts/browser-journey-roles.js`를 순서대로 실행합니다. 브라우저 검사는 실제 SIWE/BFF/Core/PG를 사용하며 Dojang과 체인 거래는 **로컬 Anvil 한정**입니다. 외부 GIWA 거래나 실제 모델 응답으로 간주하지 않습니다. 공개 배포는 `scripts/smoke-auth.ts`의 임시 무자금 지갑으로 조회·권한만 확인합니다.

OpenAI 실호출, Bojagi, Reown QR 연결, 사용자 서명 GIWA 거래의 기존 미완료 상태는 이번 UX 개편으로 완료되지 않습니다.
