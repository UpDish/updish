# 발표 시연 v0.3 — 2026-10-31

기술 스택은 승인된 v0.2를 유지하고, 팀 발표자료에 맞춰 상품·화면·분배 흐름을 개편했다. 음식점 본점의 참고 매출을 보고 **2호점 개설 자금 모집에 참여하고, 2호점의 확정 매출에 따른 분배를 확인**하는 시연이다. 실제 발행·현금 투자·업비트 계정 연동을 제공하는 서비스는 아니다.

`presentation-v03` CSV는 별도 경로에 고정했다. 본점 과거 6개월 CSV는 참고 차트에서만 사용한다. 두 자료 모두 가상이며 CSV 제출·타 지갑 마감·산정·별도 승인 전에는 승인 원장이 아니다. 기존 3,600단위·3%의 과거 실행과 읽기 전용 예시는 보존한다.

## 업비트 조사에서 반영한 구조

2026-10-31 공식 자료의 중복 제거 이미지 69개를 확인했다. 모바일 화면 포함 46개, PC 화면 9개, 구조도 4개, 프로모션 10개다. 이는 현재 앱을 직접 설치해 전 화면을 검증했다는 뜻은 아니다. 원본 이미지와 팀 발표자료는 공개 코드 저장소에 재배포하지 않았다.

| 확인한 패턴 | UpDish 적용 |
| --- | --- |

| 투자 화면에 운영 기능을 섞지 않음 | 가게·검토·정산은 계정 메뉴에서 진입하는 업무 콘솔 |

## 구현 경계

- Core는 별도 지갑 검토, 자료 소유권, 최신 승인 정산, 청약 멱등성, 실보유 발행 수량, 예치 상태를 검사한다. 새 수령 API는 본인 영수증만 반환한다. 운영자는 현재 실행의 작업과 자신의 과거 수령만 본다.
- `UpDishDemoCash`는 소수점 없는 고정 발행 테스트 자산이다. `UpDishDistribution`은 검증된 수량·정산 기록 계약과 특정 실행·상품에 묶인다. 운영 지갑의 정확한 사용 승인 후 예치하고, 이미 발행된 보유 비율과 전체 pool 한도 안에서만 분배한다.
- 브라우저가 지갑에 거래 서명을 요청한다. 서버는 실제 발신자·대상·입력·영수증·safe 블록·계약 기록을 대조한다. 제출 해시는 응답 유실 시 복구하며 미확인 거래를 자동 재송금하지 않는다. 개인 키를 서버에 보관하지 않는다.
- 하향 정정 시 과거 수령은 삭제·회수하지 않는다. 예치금은 이전 최대 예치액을 반영하며, 이미 받은 DEMO가 정정 의무액 이상이면 추가 분배하지 않는다. 과거 버전 거래가 대기 중이면 새 버전 예치를 막는다.
- 가상 배경 9,900단위는 DB 시연만 한다. 발행·지갑 분배에서 제외되므로 100단위 실제 시연 지갑에만 30,000 DEMO를 보낼 수 있다. 남은 자산이 전부 분배됐다고 표시하지 않는다.
- Agent는 공개 집계 또는 본인 승인 근거를 읽는다. 원화 의무액과 확인된 DEMO 수령·추가 수량은 서버가 계산한다. 수령 변경 시 설명 캐시도 바뀐다. 채팅은 거래를 실행하지 않는다.
- Dojang TESTNET FAUCET과 UPBIT KOREA는 별개다. Bojagi SDK·테스트 접근은 확보되지 않아 `NOT_CONNECTED`를 유지한다. 일반 ERC-20 전송을 Bojagi 비공개 분배로 부르지 않는다.
